1. What it is

Sansad Combat is a satirical 2D-fighter-in-a-3D-world that runs in any browser, on desktop (keyboard) and on phones (touch controls, installable as a PWA). It has a roster of 9 fighters in two factions (NDA and INDI Alliance), VS CPU with three difficulty levels, local 2-player, three arenas, per-character specials, grabs and slams, voices, synthesised sound effects, and a shareable result card. It is deployed on Vercel.

3. Architecture at a glance

Host layer: Phaser Game (src/main.ts, src/scenes)Boot, Menu, CharacterSelect, Fight, Result scenes. Viewport fitting, input devices (keyboard, touch), audio unlock.
InputSource (keyboard, touch, AI) ↓     MatchState (read-only snapshot) ↑
Simulation core: src/core (no DOM, no Phaser, no three) Match.step(rawMs) runs rounds, phases, hit-stop and slow-mo, using CombatSystem, Fighter state machine, Projectile, specials, AIController with difficulty profiles, and fighter-data validation. Emits an immutable MatchState every frame.
MatchState ↓
Renderers (src/renderers, src/render3d)FightRenderer interface. Stage3D (three.js, default) and PhaserRenderer (flat 2D fallback). Arenas, crowd, figures, GLB models, cutouts, camera.
Presentation (src/ui)HTML HUD overlay, news ticker, taunt bubbles, hit sparks, 9 special-move FX classes, touch controls.
Systems and shareSynth SFX and voices, result-card canvas, native share or WhatsApp.
Data (src/characters/data, src/content, public/assets)9 fighter JSON files (checked by a JSON Schema and a runtime validator), arena texts and palettes in texts.json, SVG art with a manifest, voices.

Key rule: dependencies point one way. Everything outside src/core only reads MatchState. The compiler enforces it: npm run build runs tsc -p src/core with no DOM or engine types available, so a violation fails the build.

4. How a frame works

Keyboard / Touch / AI→ InputState per fighter→ Match.step(dt)→ CombatSystem: hit, block, grab, slam→ MatchState snapshot + events→ Renderer, HUD, FX, SFX
  • Frame clamp and hit-stop. MAX_FRAME_MS bounds big frame gaps (tab switches); hit-stop and KO slow-motion are applied inside the core so every consumer stays in sync.
  • Controllers are pluggable. A fighter is driven by an InputSource (keyboard, touch, or the AIController); the same interface leaves room for a network source.
  • AI. A small state machine (approach, attack, defend, retreat) with perception of distance, reach and incoming threats, tuned by easy, normal and hard profiles (reaction time, aggression, block and special chances).
  • Events, not polling. Hits, blocks, KOs and special start/end are emitted as events; SFX, sparks and camera shake subscribe to them.

5. Data-driven fighters

Each fighter is one JSON file: stats, body box, pose set, move frame data (startup, active, recovery, damage, hit-stun, block-stun, knockback, hitbox), special definition, taunts, win quote, faction, a 3D figure description, and an SVG rig description. FighterRegistry loads every file in the folder via a Vite glob and validates it against the schema; invalid data logs a warning instead of crashing. Balance and content changes need no engine code.

Three visual tiers per fighter

TierUsed when
GLB modelThe JSON has a model block; animation clips are crossfaded by action, root motion stripped, capsule shown until the file loads
Procedural figureThe JSON has figure; a 3D body is built in code and posed from the rig frame
SVG cutoutFallback; hand-authored SVG art sliced on a standard skeleton and animated by an angle-based rig

6. Rendering

  • Layered canvases. A transparent Phaser canvas sits over a three.js canvas. Phaser draws UI and 2D FX; three draws the world. stage.project() maps world points to screen so 2D overlays line up with 3D bodies (1 world unit = 100 game px).
  • Renderer abstraction. FightRenderer is implemented by Stage3D and PhaserRenderer. The three renderer is the default; without WebGL the game falls back to Phaser automatically, and ?renderer=phaser forces it.
  • Arenas. Each arena (Sansad, India Gate, Jantar Mantar) is a builder returning an Arena object (scene root, background, fog, update, cheer, placards). They are built lazily and toggled by visibility. Placard and ticker text lives in texts.json.
  • Cinematics. Specials trigger a cutscene camera and slow-motion through windingUp(state) from the core.

7. Special-move FX framework

Specials are projectile definitions with an fx id. A factory maps the id to a class (ConstitutionFx, BulldozerFx, CycleFx, LathiFx, PanjaFx, BroomStormFx, MicDropFx, BaarishFx, JaaduFx) built on shared helpers in kit.ts (puffs, gathers, floating text, finalState). Effects read state only and track projectiles by id, since a projectile is removed the frame it dies.

8. Mobile, PWA and deployment

  • Landscape fullscreen web-app manifest, touch controls with multi-touch, fullscreen, pause and back buttons.
  • iPhone Safari bar hiding handled with a visual-viewport fit and a scroll trick; audio unlocked on the first gesture.
  • Vercel: npm ci then npm run build; /assets/* cached for a year as immutable (changed art is renamed, not overwritten), manifest always revalidated, nosniff and referrer-policy headers.

10. Design decisions and trade-offs

DecisionReasoning
Simulation separated from renderingLets the AI and balance run headless, lets the renderer be swapped (3D to 2D fallback) and makes refactors checkable by comparing traces
Everything about a fighter in JSONAdding or rebalancing a character is a data change; one schema validates all
Two canvases instead of one enginePhaser is strong at scenes and input, three at 3D; the cost is projecting coordinates between them
Synthesised SFXSmall bundle and no licensing issues; only a block clip and voice lines are audio files
Immutable asset cachingFast repeat loads; the cost is renaming files when art changes
Fallback rendererDevices without WebGL still play; keeping it alive requires the interface discipline

11. Honest limitations

  • No automated unit-test suite in the repo; verification is typecheck, build, headless simulations and Playwright smoke scripts.
  • The AI uses Math.random for reaction jitter, so AI matches are not bit-for-bit reproducible without seeding it.
  • Online multiplayer is not implemented; the InputSource abstraction is the intended hook.
  • Character names and faction names are satirical parody; this is an entertainment project.
